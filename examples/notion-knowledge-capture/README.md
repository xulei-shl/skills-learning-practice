# Notion 知识捕获

将对话、讨论和见解转换为结构化的 Notion 文档。捕获聊天上下文中的知识，适当格式化，并保存到正确的位置进行组织。

## 功能概述

- **对话转文档**：从聊天记录中提取关键信息
- **结构化存储**：支持多种内容类型（概念、指南、FAQ、决策记录等）
- **智能分类**：根据内容类型选择合适的存储位置
- **知识关联**：自动建立页面链接，提高可发现性

## 快速开始

当需要将信息保存到 Notion 时：

1. **提取内容**：从对话上下文中识别关键信息
2. **确定类型**：分类为概念、指南、FAQ、决策记录等
3. **查找位置**：使用 `Notion:notion-search` 找到合适的 wiki 页面或数据库
4. **创建页面**：使用 `Notion:notion-create-pages` 保存内容
5. **建立链接**：从相关中心页面链接，确保内容可被发现

## 工作流程

### 第1步：识别要捕获的内容

从对话上下文中提取：
- 关键概念和定义
- 做出的决策及理由
- 操作指南和流程
- 重要见解或学习
- 问答对
- 示例和用例

### 第2步：确定内容类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| 概念/定义 | 解释什么是某个概念 | 技术术语、理论背景 |
| 操作指南 | 步骤化的操作说明 | 教程、最佳实践 |
| 决策记录 | 记录架构/产品决策 | 技术选型、方案选择 |
| FAQ | 问答形式的问题解答 | 常见问题、知识问答 |
| 会议总结 | 会议讨论的要点记录 | 回顾会议、同步会议 |
| 学习总结 | 事件或项目的经验教训 | 复盘、Post-mortem |

### 第3步：格式化内容

根据内容类型选择合适的结构：

**概念类**：
```
概述 → 定义 → 特征 → 示例 → 使用场景 → 相关链接
```

**操作指南类**：
```
概述 → 前置条件 → 步骤（编号）→ 验证 → 故障排除 → 相关链接
```

**决策记录类**：
```
背景 → 决策 → 理由 → 考虑的方案 → 影响 → 实施计划
```

**FAQ 类**：
```
简短答案 → 详细解释 → 示例 → 使用场景 → 相关问题
```

### 第4步：选择目标位置

| 位置 | 适用场景 |
|------|----------|
| 通用 Wiki | 一般知识库 |
| 项目 Wiki | 项目特定知识 |
| 文档数据库 | 结构化文档 |
| FAQ 数据库 | 问答知识库 |
| 决策日志 | 架构/产品决策 |
| 团队 Wiki | 团队特定知识 |

### 第5步：创建页面

使用 `Notion:notion-create-pages`：
- 设置合适的标题
- 使用模板格式化内容
- 设置数据库属性（如果适用）
- 添加标签/分类
- 链接相关页面

### 第6步：确保可发现性

新页面创建后，确保它能被找到：

1. **更新索引页**：添加到 Wiki 目录
2. **设置属性**：正确的标签、状态
3. **链接父页面**：从相关项目/团队页面链接

示例：
```
Notion:notion-update-page
page_id: "team-wiki-homepage-id"
command: "insert_content_after"
selection_with_ellipsis: "## 操作指南..."
new_str: "- <mention-page url='...'>如何部署到生产环境</mention-page>"
```

## 最佳实践

### 内容提取

| 场景 | 提取内容 |
|------|----------|
| 聊天讨论 | 关键点、结论、资源、行动项、问答 |
| 问题解决 | 问题陈述、尝试的解决方案、解决方案、为何有效 |
| 知识分享 | 解释的概念、示例、最佳实践、常见陷阱 |
| 决策讨论 | 问题、选项、权衡、决策、理由、下一步 |

### 格式规范

- **标题结构**：使用 `#`（标题）、`##`（节）、`###`（小节）
- **写作风格**：以概述开头，使用列表，保持段落简短
- **链接方式**：链接相关页面，提及人员，引用资源
- **元数据**：包含日期、作者、标签、状态

### 组织和索引

- **Wiki 索引**：按章节组织（入门、操作指南、参考、FAQ、决策）
- **分类页面**：创建带有概述和文档链接的着陆页
- **标签策略**：一致的标签（技术/工具、主题、受众、状态）

### 更新管理

- **创建新的**：内容充实（>2段），会被多次引用，属于知识库
- **更新现有的**：补充现有主题、纠正信息、扩展概念
- **版本控制**：为重大更改添加更新历史部分

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| 不确定保存位置 | 默认为通用 Wiki，后续可以移动 |
| 内容碎片化 | 将相关片段组织成连贯文档 |
| 内容已存在 | 先搜索，如果合适则更新现有内容 |
| 风格太随意 | 清理语言同时保留原始见解 |
