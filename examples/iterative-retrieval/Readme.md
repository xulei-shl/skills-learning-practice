# 迭代式子代理检索协议
---
**名称**：iterative-retrieval  
**描述**：派遣子代理并自动执行优化循环，直到收集到足够的上下文信息
---

当派遣子代理从某一来源（如文稿、文档、代码库、外部数据）检索信息时，请遵循以下协议：

## 📋 阶段 1：初始派遣
1.  明确**核心目标**——这些信息将支持什么决策或行动？
2.  定义**初始查询**——需要检索的具体内容
3.  向子代理发送查询，同时附上目标上下文
4.  保存返回的代理ID

---

## 🧐 阶段 2：充分性评估
收到子代理的摘要后，执行严格评估：

#### 自问以下问题：
- 摘要中是否存在目标所需填补的信息缺口？
- 子代理是否提到了我没要求但现在发现需要的相关信息？
- 返回的内容中是否存在模糊之处，需要从来源进一步澄清？
- 仅依靠这些信息，我是否有信心继续推进任务？

#### 决策：
- 如果**信息充分** → 继续执行任务，记录代理ID以便未来可能的恢复
- 如果**信息不足** → 进入阶段3

---

## ✏️ 阶段 3：优化请求
使用代理ID恢复请求，并执行以下操作：
1.  确认初始返回内容中哪些部分是有用的
2.  **明确说明**需要补充的具体上下文，以及**原因**
3.  询问子代理是否注意到了相关但未包含在返回结果中的信息

---

## 🔄 阶段 4：循环
重复阶段2-3，直到满足以下任一条件：
- 信息充分性达标，或
- 达到最多3次优化循环（防止无限循环），或
- 子代理确认来源已无更多信息

---

## 📤 输出格式
向用户汇报或继续工作时，请记录：
- 总共使用的优化循环次数
- 超出初始请求范围所收集的额外上下文
- 代理ID，以便未来需要时恢复任务
